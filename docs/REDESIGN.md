### 1.2 核心问题诊断

#### 问题 1: 概览页信息严重不足 ❌

**现状**:
- 只有 2 个统计卡片（活跃服务数、大模型请求数）
- 服务列表是硬编码的 mock 数据
- 没有系统健康状态总览
- 没有关键指标趋势
- 没有告警/异常提示

**用户痛点**:
> "打开 Dashboard，我看到的是什么？24/28 个活跃服务？然后呢？我不知道系统是否健康，不知道有没有问题需要处理。"

#### 问题 2: 页面间缺乏关联 ❌

**现状**:
- 每个页面独立运行，没有数据流转
- 概览页无法快速跳转到问题页面
- 没有全局搜索结果关联
- 没有面包屑导航

**用户痛点**:
> "我发现 L4 域健康有问题，但我不知道这个问题会影响哪些服务，也不知道去哪里看详细信息。"

#### 问题 3: 大量页面是空壳 ❌

**现状**:
- Compute (算力): 只有 131 行，基本是空页面
- Settings (设置): 只有 121 行，配置项很少
- Observability (可观测): 只有 134 行，没有实际数据
- Sandbox (沙箱): 只有 129 行，功能单一

**用户痛点**:
> "点击这些页面，看到的是空白或者极简的内容，感觉产品还没做完。"

#### 问题 4: 缺少关键功能 ❌

**缺失功能**:
- ❌ 告警中心（统一的告警列表和处理）
- ❌ 任务中心（Agent 任务的统一视图）
- ❌ 日志查看器（实时日志流）
- ❌ 性能监控（CPU/内存/磁盘/网络）
- ❌ 配置管理（在线修改配置）
- ❌ 用户管理（权限和角色）
- ❌ 审计日志（操作记录）

#### 问题 5: 数据可视化不足 ❌

**现状**:
- 大部分页面是表格和文本
- 没有图表（折线图、柱状图、饼图）
- 没有实时数据流
- 没有时间范围选择器

**用户痛点**:
> "我想看过去 24 小时的健康趋势，但没有任何图表，只有静态的数字。"

| 功能 | K8s Dashboard | Cockpit UI | 差距 |
|------|---------------|------------|------|

### 3.3 核心功能增强

#### 3.3.1 告警中心 (Alert Center)

**功能**:
- 活跃告警列表（按严重程度排序）
- 告警详情（关联服务、影响范围、建议操作）
- 告警处理（确认、静默、解决）
- 告警规则配置（可视化规则编辑器）
- 告警历史（查询和分析）
- 通知渠道配置（Slack/邮件/企业微信）

**数据源**:
- L4 域健康告警
- 服务健康告警
- 性能阈值告警
- 自定义规则告警

#### 3.3.2 日志查看器 (Log Viewer)

**功能**:
- 实时日志流（WebSocket）
- 日志搜索（全文搜索、正则表达式）
- 日志过滤（按服务、级别、时间）
- 日志导出（CSV、JSON）
- 日志分析（错误统计、趋势图）

**数据源**:
- 各服务日志文件
- 系统日志
- 审计日志

#### 3.3.3 任务中心 (Task Center)

**功能**:
- 活跃任务列表
- 任务详情（进度、日志、产出物）
- 任务操作（暂停、恢复、取消）
- 任务调度（定时任务、依赖任务）
- 任务历史（查询和分析）

**数据源**:
- .omo/tasks/ 目录
- Agent 运行时任务
- 定时任务调度器

#### 3.3.4 性能监控 (Performance Monitoring)

**功能**:
- CPU/内存/磁盘/网络实时监控
- 容器/Pod 状态监控
- 自定义指标监控
- 性能基线对比
- 性能告警配置

**数据源**:
- 系统指标采集器
- 容器运行时 API
- 自定义指标端点

### 3.4 数据可视化增强

#### 3.4.1 图表库选择

推荐使用 **Recharts** 或 **ECharts**:
- React 原生支持
- 丰富的图表类型
- 良好的性能
- 活跃的社区

#### 3.4.2 图表类型

| 场景 | 图表类型 | 示例 |
|------|----------|------|
| 趋势分析 | 折线图 | 健康分数趋势、请求数趋势 |
| 占比分析 | 饼图/环形图 | 服务状态分布、告警级别分布 |
| 对比分析 | 柱状图 | 域信号数对比、性能指标对比 |
| 实时数据 | 面积图 | CPU/内存使用率、网络流量 |
| 关系分析 | 桑基图 | 服务调用流向、数据流转 |
| 分布分析 | 直方图 | 响应时间分布、错误率分布 |

3. **图表集成** - 数据可视化
